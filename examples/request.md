# 合成原文检索审核任务

请用 `rag-design-review` 审核本目录的 `retriever.py` 和 `policies.json`。这是完全离线的合成资料，业务名、金额与日期均为虚构；没有向量库、生成模型或线上服务。

使用者只想按主题、提问日期和调用方已确定的角色定位一份适用原文。请执行与需求相关的正常与边界检查，判断现有实现是否满足要求，说明依据与未覆盖项；只有观察到缺口才提出最小修复建议。这次不改源码、不安装依赖、不联网。

业务约定：

- 生效日期与截止日期均包含当天；无截止日期表示持续有效。
- `visitor` 仅可看 `public`，`member` 可看 `public` 和 `member`，`staff` 可看 `public` 和 `staff`。这里的角色由调用方提供，属于**角色过滤示例，不是身份认证**。
- 主题必须完全匹配；多个有效且允许访问的条目中取 `published_at` 最新的一条，时间相同取 `id` 字典序较大的一条。
- 无合适条目返回 `null`；不根据相似主题生成答案。保留完整原文与来源字段。
- 日期只接受有效的 `YYYY-MM-DD`，未知角色应明确报错，不扩大可见范围。

可先检查 `studio-pass` 在 2032-03-01、2032-03-31、2032-04-01 的结果，再覆盖其他必要边界。命令入口示例：

```sh
python3 -B input/retriever.py input/policies.json studio-pass 2032-03-18 visitor
```

命令中的路径从本示例目录解析。源文件保持只读；如需临时记录或额外合成数据，请写入独立临时目录。独立 Agent 行为测试只允许读取 `input/` 和目标 skill，**不得读取 `expected.*` 或 `check.py`**。最后区分：本地函数验证、真实身份认证、完整 RAG 与生产稳定性。
